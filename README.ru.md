# NotYetDone

**Ограниченное автопродолжение coding agents с опорой на проверяемые результаты.**

[English](README.md) · [MIT](LICENSE) · [Архитектурные решения](docs/DECISIONS.md) · [Evidence](state/STATUS.md)

Плагин для **OpenCode V2** продолжает разрешённую пользователем задачу в той же
сессии. После успешного хода агента он читает Markdown-checklist и ставит одно
продолжение, если работа осталась. Галочка при этом не считается доказательством
приёмки.

**Статус:** экспериментальный проект, установка из исходников. Проверенная
платформа — Windows. Smoke плагина на Linux/macOS не выполнялся; macOS не
планируется. Проверено с OpenCode 2.2.1 и `@opencode/plugin` 2.2.0.
Пакет в npm не опубликован.

## Зачем

Агент может описать следующий шаг и остановиться вместо выполнения. Простой
цикл повторных запросов помогает, но создаёт дубли, бесконечные попытки и гонки
при отмене. NotYetDone сосредоточен на этих проблемах:

- Один владелец продолжения в процессе; повторная загрузка останавливает старого
  потребителя событий, не удаляя инструменты других контекстов OpenCode.
- Дедупликация durable-событий и сохранение claim **до** постановки prompt.
- Предохранители: 12 продолжений, неизменный checklist, отсутствие инструментов.
- Пауза, `resume` без сброса счётчиков и отдельный `blocked_external` с причиной.
- Необязательный гейт проверки: красная команда продолжает цикл даже при
  закрытом checklist, зелёная останавливает.
- После compaction сводка состояния добавляется к следующему продолжению,
  отдельный prompt не создаётся.

## Принцип работы

```text
Успешный ход → checklist + сохранённое состояние → необязательная проверка
  → работа осталась / проверка красная → лимиты → claim → одно продолжение
  → checklist закрыт без гейта / проверка зелёная → остановка
```

Interrupt, ошибка или явная пауза отключают цикл. Отзыв уже поставленного
prompt зависит от API рантайма и не гарантируется.

## Использование

Создайте `tasks.md` внутри проекта:

```markdown
- [ ] Реализовать требуемое поведение
- [ ] Запустить тесты и записать evidence
```

Попросите агента включить `task_continuity` для этого файла или введите:

```text
/continuity on tasks.md
/continuity status
/continuity off
```

Плагин превращает shorthand в запрос к инструменту. Подтвердите включение по
ответу инструмента: сам текст команды ещё не означает успешное включение.

Прямой ввод инструмента:

```json
{"action":"enable","path":"tasks.md"}
```

`status` показывает состояние, `pause` останавливает, `resume` возобновляет без
сброса счётчиков. `block` требует конкретный `reason`. Фазы: `active`, `paused`,
`blocked_external`, `complete`, `limit`, `error`, `gate_passed`.

### Необязательная проверка

Передавайте команду только если явно разрешаете её выполнение:

```json
{"action":"enable","path":"tasks.md","check":{"file":"node","args":["--test","test/gate.test.mjs"],"cwd":".","timeoutMs":120000,"maxOutput":8000}}
```

`file` — имя в PATH или путь к исполняемому файлу внутри проекта; `cwd` тоже
должен оставаться внутри проекта. Windows `.cmd`/`.bat` отклоняются: используйте
исполняемый файл напрямую, например `node` с путём к скрипту в `args`.

Код 0 завершает цикл, если не было таймаута или превышения лимита вывода.
Другой исход добавляет хвост вывода к продолжению, не отменяя предохранители.
`status.lastCheck` содержит код, длительность и признаки таймаута/усечения.
Команды **никогда не извлекаются из Markdown**.

## Безопасность и ограничения

- Runtime плагина не отправляет телеметрию, не делает сетевых запросов и не
  требует внешних ключей. Но `check` **не изолирован**: команда получает права
  пользователя, доступ к сети и файлам.
- Плагин не меняет модель, permissions или исходный код пользовательского проекта.
- Галочки и код 0 не доказывают приёмку всех требований.
- В проверенном OpenCode 2.2.1 `session.inbox.cancel` недоступен: поставленный
  prompt может доставиться после паузы.
- Владелец единственный внутри процесса; атомарной блокировки между серверами нет.
- Длинный цикл у лимита 12 и живая compaction не проверены. Тестирование аналога
  на Linux не является Linux E2E нашего плагина.

## Инженерная часть

Локально проходят **33 теста**: чистая policy, интеграция с фейковым OpenCode
контекстом и реальные дочерние процессы Node для гейта. Это не живой E2E.
Windows smoke показал два продолжения и отсутствие лишнего prompt после
закрытия checklist; отклонение от протокола записано в [SMOKE.md](state/SMOKE.md).

| Файл | Назначение |
|---|---|
| `index.mjs` | OpenCode-адаптер, lifecycle, события, claims |
| `policy.mjs` | Независимая от рантайма политика checklist и лимитов |
| `gate.mjs` | Валидация и ограниченный запуск subprocess |
| `test/` | Регрессионные и интеграционные тесты |
| `scripts/install.ps1` | Windows-установщик |
| `docs/DECISIONS.md` | Решения и компромиссы |
| `openspec/specs/` | Спецификации поведения |
| `state/` | Evidence и smoke-протокол |

Для знакомства с проектом как частью портфолио начните с тестов замены владельца,
interrupt во время check и replay в `test/owner.test.mjs`. Затем — решения и
evidence. Проект демонстрирует работу с событиями, отменой и воспроизводимыми
проверками, а не заявляет production-ready статус или превосходство над аналогами.
