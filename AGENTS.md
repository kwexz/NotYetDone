# Правила работы в NotYetDone

Проект: плагин автоматического продолжения для coding agents. Сейчас один
адаптер — OpenCode V2. Windows — проверенная платформа, macOS/Linux — нет.

## Цикл

1. Прочитай `START_HERE.md`, `state/STATUS.md`, `docs/DECISIONS.md` и **один**
   пункт из `docs/ROADMAP.md`. Не читай весь `docs/research/` подряд.
2. Сформулируй проверяемый критерий → реализуй → тесты → измерь → коммит →
   запиши evidence в `state/STATUS.md`.
3. Разделяй `verified`, `not-run`, `blocked_external`, `failed`. Не называй мок
   реальным E2E. Не выдумывай время, стоимость, охват платформ.
4. Не переходи к следующей фазе, пока текущая не прошла acceptance.

## Жёсткие инварианты

- **Один владелец продолжения.** Не добавлять второй механизм рядом.
- Stop/interrupt важнее любого события успеха. Отмена должна охватывать
  callbacks, таймеры и уже поставленные в очередь prompts.
- Идемпотентность: одно durable-событие не должно приводить к двум prompt.
- Галочка ≠ доказательство. Плагин не объявляет acceptance пройденным и не
  выполняет произвольные команды из task-файлов.
- `blocked_external` — отдельное состояние, оно прекращает цикл с причиной.
- Никакой телеметрии, сетевых вызовов и внешних ключей в runtime плагина.
- Плагин не меняет модель, permissions, настройки пользователя и код проекта.
- Не публиковать, не тегировать и не пушить без явной просьбы.

## Проверки

```powershell
npm ci
npm test
npm run check
```

Живой smoke — только по `state/SMOKE.md`, в отдельной короткой сессии, не на
длинной продуктовой задаче.

## Коммиты

Маленькие атомарные коммиты по фазам, в отдельной ветке. Не force-push.
Не коммитить секреты, токены, приватные данные.
