# Spec Delta

## Purpose

Гарантирует, что одно успешное исполнение даёт не больше одного продолжения и
что остановка пользователя отменяет всё, что ещё может вернуть агента к работе.

## ADDED Requirements

### Requirement: Единственный владелец продолжения

Плагин SHALL держать не более одной активной подписки на события продолжения в
пределах процесса. Повторная инициализация MUST освобождать предыдущую
подписку, а не добавлять вторую.

#### Scenario: Повторная загрузка плагина

- **WHEN** runtime повторно загружает плагин в том же процессе
- **THEN** активна ровно одна подписка, предыдущая освобождена

#### Scenario: Параллельные экземпляры

- **WHEN** плагин инициализирован несколько раз до обработки первого события
- **THEN** продолжение обрабатывает только один владелец

### Requirement: Один prompt на успешное исполнение

На одно событие `session.execution.succeeded` плагин SHALL ставить в очередь не
более одного prompt с метаданными `taskContinuity`.

#### Scenario: Одно событие — один prompt

- **WHEN** приходит одно событие `session.execution.succeeded` при незакрытом checklist
- **THEN** в очереди сессии ровно один prompt продолжения

#### Scenario: Повторная доставка события

- **WHEN** то же событие с тем же `event.id` доставлено повторно
- **THEN** второй prompt не ставится

#### Scenario: Гонка владельцев

- **WHEN** событие обрабатывают два экземпляра одновременно
- **THEN** в очереди остаётся ровно один prompt

### Requirement: Остановка отменяет очередь

`pause`, `stop` и `block` SHALL предотвращать доставку prompt, которые уже
поставлены в очередь, но ещё не доставлены.

#### Scenario: Стоп при непустой очереди

- **WHEN** пользователь говорит «стоп», а в очереди есть не доставленный prompt продолжения
- **THEN** prompt не доставляется, `status` показывает `enabled: false` и причину

#### Scenario: Нет API отзыва

- **WHEN** runtime не предоставляет способ отозвать сообщение из очереди
- **THEN** ограничение фиксируется в `state/STATUS.md` как `blocked_external` или `not-run` с evidence, а не объявляется исправленным

### Requirement: Закрытый checklist не продолжается

Если после успешного исполнения все пункты checklist отмечены, плагин SHALL NOT
ставить продолжение и MUST перевести состояние в `Checklist complete`.

#### Scenario: Последний пункт закрыт

- **WHEN** успешное исполнение завершилось, а в checklist не осталось неотмеченных пунктов
- **THEN** продолжение не ставится, `status` показывает `Checklist complete`

#### Scenario: Нет чекбоксов

- **WHEN** в файле нет ни одного чекбокса
- **THEN** контроль выключается с причиной, продолжение не ставится

### Requirement: Прерывание важнее успеха

`session.execution.interrupted` и `session.execution.failed` SHALL выключать
контроль до явного `resume` и MUST NOT порождать продолжение.

#### Scenario: Прерванное исполнение

- **WHEN** приходит `session.execution.interrupted`
- **THEN** контроль выключен, новых prompt нет

#### Scenario: Успех после прерывания

- **WHEN** после прерывания приходит успешное исполнение без `resume`
- **THEN** продолжение не ставится
