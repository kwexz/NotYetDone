# Proposal

## Why

Живой smoke 2026-10-29 на OpenCode v2.2.1 провалился: одно событие
`session.execution.succeeded` дало четыре автопродолжения, два из них пришли
после закрытия checklist, четвёртое — после явного `action=pause`. Фаза 0
дорожной карты не принята, поэтому фазы 1–6 заблокированы. Нужен один план,
который сначала закрывает дефект владельца продолжения, а затем доводит
остальные фазы до проверяемых критериев.

## What Changes

**Фаза 0 — стабилизация (блокер).**

- Один владелец продолжения: повторный `setup` не оставляет вторую живую
  подписку на события.
- Владение событием фиксируется до постановки prompt, чтобы одно событие давало
  не больше одного prompt даже при нескольких экземплярах плагина.
- `pause` / `stop` отменяет не только будущие, но и уже поставленные в очередь
  prompt. Если API V2 этого не позволяет — это фиксируется как ограничение с
  доказательством, а не замалчивается.
- Повторный живой smoke: 2 автопродолжения, 0 лишних, финальное состояние
  `Checklist complete`.

**Фаза 1 — стагнация.**

- Считать tool-события между двумя успешными исполнениями.
- Ноль инструментов + неизменный digest checklist = стагнация, отдельный
  счётчик.
- `status` показывает оба счётчика.

**Фаза 2 — детерминированный гейт.**

- Необязательный `check` в состоянии: команда + рабочая директория.
- Запуск только по явному согласию пользователя, с таймаутом и лимитом вывода.
- Код 0 — продолжение разрешено; иначе продолжение с хвостом вывода.
- Новое решение в `docs/DECISIONS.md` фиксирует границу с D7 (команды из
  task-файлов по-прежнему запрещены).

**Фаза 3 — resume и `blocked_external`.**

- `action=resume` без сброса счётчиков.
- `blocked_external` — отдельное состояние с причиной и списком сделанного.
- `status` различает paused / blocked / complete / limit.

**Фаза 4 — восстановление после compaction.**

- Проверить, какие события компакции есть в V2.
- При включённом контроле возвращать состояние задачи после сжатия.
- Если события нет — честный `not-run` с описанием, а не имитация.

**Фаза 5 — решение о публикации.**

- Сравнить с `untildone` на Linux/macOS (сейчас `blocked_external`).
- Проверить, остался ли сценарий, который не закрывают аналоги.
- Записать явное решение в `DECISIONS.md`. Публикация, тег и push — только по
  отдельной просьбе пользователя.

**Фаза 6 — другие рантаймы.**

- В этот change не входит. Перечислена как gated-задача: начинать только после
  приёмки фаз 0–5 и только отдельными пакетами.

**Не меняется:** никакой телеметрии, сетевых вызовов и внешних ключей; плагин
не меняет модель, permissions и код проекта; команды, найденные в task-файлах,
не исполняются; галочка в checklist не считается доказательством.

## Capabilities

### New Capabilities

- `continuation-safety`: ровно одно продолжение на успешное исполнение, один
  владелец подписки, отмена очереди, закрытый checklist не продолжается.
- `continuation-limits`: лимиты, обнаружение стагнации по tool-событиям и
  digest, счётчики в `status`.
- `verification-gate`: opt-in детерминированная проверка перед продолжением,
  таймаут и лимит вывода.
- `session-recovery`: resume без сброса счётчиков, `blocked_external`,
  различимые состояния, восстановление после compaction.

### Modified Capabilities

Нет: проект ещё не имеет спецификаций OpenSpec, все перечисленные возможности
вводятся впервые.

## Impact

- Код: `index.mjs`, `policy.mjs`, `test/*.test.mjs`, `scripts/install.ps1`.
- Состояние и evidence: `state/SMOKE.md`, `state/STATUS.md`.
- Решения и карта: `docs/DECISIONS.md`, `docs/ROADMAP.md`.
- Зависимости: новых нет, runtime остаётся без сети и без внешних ключей.
- Платформы: приёмка на Windows; macOS/Linux остаются `not-run` до отдельного
  прогона.
